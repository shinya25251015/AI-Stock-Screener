## 3. 構造的な学び

1. **正常化ROEは「判定を覆す装置」ではなく「覆らないことを確かめる装置」でもある。**
   確認済み6例のうち判定が覆ったのは日本カーボン(5302)と大同信号(6743)の2件で、いずれも
   **実績ROEがフロア6%の近傍（9.08%・6.87%）にあった**。今回のF-4は実績ROEが14〜40%か、
   逆に0.72%と極端で、**フロアからも比1.0からも遠い**ため振れ幅が結論に届かない。
   → **特別損益チェックの優先順位は「フロアや比1.0からの距離」で決めるのが合理的。**
   引き継ぎ書§9の優先1（鉄建建設6.79%・名工建設7.49%・第一建設工業7.14%・
   日本軽金属HD6.47%）が正しい並びであることが、逆側から裏づけられた。

2. **一過性は「利益を膨らませる側」だけではない。** さくらインターネットの国庫補助金は
   固定資産圧縮損と同額で相殺されており、片方だけを見ると誤る。
   **特別利益・特別損失は必ず純額で戻す**（`normalized_roe_from_special_items` はそう実装済み）。

3. **Yahooの実績ROEは原本と一致する。疑うべきは値ではなく中身。**
   今回JGAAP5社すべてで小数第2位まで再現した。つまり「準一次だから危ない」のではなく、
   **「実績ROEという指標そのものが一過性を含む」**のが問題の所在。

4. **成長継続軸は閉じたままでよい。** 9社を原本まで降りて再確認しても発火前はゼロ。
   「連続増収増益ランキング」は**長く伸びた結果として大きくなった会社**の一覧であり、
   サイズ・バリュエーションの両面でこのプロジェクトのテーゼと構造的に噛み合わない。

## 4. 実装に落としたこと

`screener/disclosure.py`（新規・テスト18件）で、この作業を1コマンドにした。
テストは全体で 45件 → **69件**。

```bash
python -m screener.cli special-items 1815 1869.N 1799 5703   # 引き継ぎ書§9の優先1
```

- 開示一覧を **Yahoo（直近1年）と kabupro（数年ぶん）の両方**から引く。
  今回、片方だけでは9社中4社に届かなかった。
- 本決算短信だけを選ぶ（四半期・中間・訂正を除く）。
- PDFを読み、特別損益・法人税等・非支配株主・（参考）自己資本を拾って正常化ROEを出す。
- **根拠の行そのものを必ず併記する**（§14）。
- **IFRS短信は自動処理しない**（特別損益の区分が無いものを読み替えない＝§8）。
- **実効税率を前期と比較する**（`valuation.TaxRateCheck` / `roe_at_tax_rate`）。
  引き継ぎ書§5の優先6「実効税率の異常を検出する関数を追加する」として明記されていた
  実装課題で、本セッションで着手した。**法定実効税率は記憶で置かず、原本から取れる
  2期ぶんの実績だけで判断する**（§8）。異常時は保守側＝高いほうの税率で引き直す。

既知の落とし穴を2つテストで固定した:

- 本文の「税金等調整前当期純利益による22,572百万円及び売上債権の減少による6,004百万円の……」
  という**文章の行**を表と取り違えない（1414・3038で実際に踏んだ）。
- 「（参考）自己資本」の単位（百万円）が損益計算書の単位（千円）と異なる場合の換算
  （3778・4417）。揃えないとROEが1000倍ずれる。

**検算**: 既知の大同信号(6743)へ通すと 実績6.88%／正常化**5.86%** を返し、
`special_items_check_2026-08-18.md` の記録（6.87%／5.93%）を再現した。
0.07ptの差は**自己資本の取り方**（本実装は期首期末平均、8/18の記録は期末ベースと推定）による。
