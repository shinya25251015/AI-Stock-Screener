# 実績ROEの特別損益チェックを、①の原本確認より前に置く（2026-08-18）

## なぜ入れたか

**実績ROEが一過性の特別利益で嵩上げされていた例が、確認済みで4件ある。**
25銘柄程度を原本まで見て4件なので、例外ではなく常態として扱う。

| 銘柄 | 実績ROE | 正常化ROE | 一過性の中身（原本） | 補正前の見え方 |
|---|---:|---:|---|---|
| 品川リフラ(5351) | 26.6% | 8% | 資産売却益 | 比0.49＝ポート最安（**割高に見せていた側の訂正**） |
| 日東紡(3110) | 27.54% | 11.28% | 固定資産売却益 | 比0.80＝発火前 → 実際は**2.22＝発見済み** |
| 日本カーボン(5302) | 9.08% | **5.55%** | 投資有価証券売却益3,530百万円 | 比0.87＝発火前・フロア通過 → 実際は**1.43＋フロア割れ** |
| 大同信号(6743) | 6.87% | **5.93%** | 投資有価証券売却益379,498千円（**2期連続**） | 比0.72＝発火前・フロア通過 → 実際は**フロア割れ** |

**日本カーボンと大同信号は、補正しない限り「発火前・品質フロア通過」に見える。**
どちらも補正すると品質フロアを割り、積立候補から外れる。

そして**大同信号では、①の原本確認（中計「PLAN2026」＋1Q短信＋本決算の3文書）を
終えてからフロア割れが判明した**。①の確認は重い作業なので、この順序だと無駄が出る。

## 何を変えたか

### 1. `normalized_roe_from_special_items()` — 補正手順を関数に固定

決算短信の連結損益計算書・貸借対照表の実額から正常化ROEを出す。

```python
from screener.valuation import normalized_roe_from_special_items

# 日本カーボン(5302) 25/12期決算短信原本（2026-02-10開示）
normalized_roe_from_special_items(
    pretax_income=7829,      # 税金等調整前当期純利益
    special_gains=3530,      # 特別利益合計（全額 投資有価証券売却益）
    special_losses=803,      # 特別損失合計（火災損失）
    tax_total=2441,          # 法人税等合計 → 実効税率を原本から算出
    minority_interest=557,   # 非支配株主に帰属する当期純利益
    equity=(52014 + 54393) / 2,  # 自己資本（期首期末平均）
)  # → 5.55%
```

`tax_total` を渡すと実効税率を原本から求める（推奨）。渡さない場合は
`effective_tax_rate` の指定、それも無ければ既定30%。
実効税率は税効果の戻し等で異常値になる期があるため0〜60%に丸めている。

### 2. 未確認を「未確認」として出す

`RoeInput.special_items_checked` を追加した。`False` のまま実績ROEで判定すると、
`ScreenResult.special_items_unverified` が立ち、フラグ文が出る。

**重要な設計判断: `passed` は落とさない。** 落とすと「未確認」と「本当に不合格」が
区別できなくなる。通過したうえで `needs_primary_check` が立つ、という二段構えにした。

```
passed = True かつ special_items_unverified = True
  → needs_primary_check = True
  → 「安さ・品質は通ったが、実績ROEの裏取りが済んでいない」
```

これは「想定内注記で覆い隠さない」（前澤工業の上場廃止・愛知電機のティッカー誤りで
2回学んだ）のと同じ考え方。**黙って通すのが一番危ない。**

### 3. 陰性の確認も記録できる

原本を見た結果「特別損益は無かった＝実績ROEをそのまま使ってよい」と分かった場合は、
`watchlist.yaml` の `verified_fundamentals` に書ける。

```yaml
verified_fundamentals:
  roe_pct: 12.0
  special_items_checked: true   # 原本で確認済み・特別損益なし
```

`normalized_roe_pct` がある銘柄は当然確認済みとして扱われる。

### 4. CLI が最後にまとめて出す

```
★ ①の原本確認より先に、実績ROEの特別損益を確認すべき銘柄:
    - 6743 大同信号（比0.72・発火前）
```

JSON出力にも `special_items_unverified` / `needs_primary_check` を追加した。

## 判定順序（更新後）

```
発掘（選定軸）
  ↓
安さ足切り（比 = 実PBR ÷ 妥当PBR）
  ↓
品質フロア（正常化ROEがあればそれで判定。両方向に効かせる）
  ↓
★ 実績ROEの特別損益チェック  ← ここを新設。①より前に置く
  ↓  未確認なら needs_primary_check が立つ
① 一次確認（原本に拡大言明があるか）  ← 重い作業。ここまで来る前に落とす
  ↓
② 定量確認 → ③ 明言
```

## 残る限界

- **特別損益の実額は自動取得できない。** finance.yahoo.co.jp からは実績ROEしか取れず、
  特別利益の有無は決算短信原本のPDFを読まないと分からない。この変更が自動化するのは
  「**確認したか／していないかの管理**」であって、確認そのものではない。
- 2期分を見る必要がある。大同信号は26/3期と25/3期の**2期連続**で特別利益があった。
  1期だけ見ると「今期はたまたま」と読み違える。
- 逆向き（一過性の**損失**で実績ROEが押し下げられている＝谷）も同じ関数で扱えるが、
  こちらは `special_gains < special_losses` になるため正常化ROEが上がる。東洋炭素の型。
